## 10. Rastreamento (Google Tag Manager)

1. Cole o ID do contêiner (formato `GTM-XXXXXXX`) em `js/gtm.js`, na linha `var GTM_ID = ''`.
2. Cada clique dispara um evento no `dataLayer`. No GTM, crie acionadores do tipo **Evento personalizado** com estes nomes:

| Evento | Quando |
|---|---|
| `whatsapp_click` | qualquer botão de WhatsApp (inclusive o envio do orçamento interativo) |
| `phone_click` | qualquer botão de ligar |
| `directions_click` | botão **Como chegar** e endereço |
| `instagram_click` / `facebook_click` | links das redes sociais |

Parâmetros enviados junto: `click_location` (ex.: `header`, `card-servico`, `barra-fixa`, `topo-servico`), `service` (nome do serviço, quando houver) e `page_path`.

3. O consentimento começa **negado** e muda para concedido quando o visitante clica em **Aceitar** no aviso de cookies (que só aparece depois que o ID do GTM for preenchido).

## 11. Como editar

- **Textos:** cada página é um `index.html` comum. Abra no GitHub, clique no lápis ✏️ e edite.
- **Cores:** todas no topo de `css/style.css`.
- **Telefone/WhatsApp:** está escrito nos links `wa.me/5511983980583` e `tel:+5511983980583`. Para trocar, use "Localizar e substituir" em todos os arquivos `.html`.
- **Foto em um card de serviço sem foto:** salve a imagem em `img/servicos/NOME.webp` (até 300 KB e 1600 px) e troque o bloco marcado com `<!-- FOTO: ... -->` por `<img src="img/servicos/NOME.webp" alt="descrição da foto">`.
- **Novo antes e depois:** salve as duas fotos em `img/resultados/` e, no `index.html`, copie um bloco `<li class="result">`, trocando as fotos, o `data-cat` (`martelinho`, `micropintura`, `polimento`, `funilaria` ou `higienizacao`), o título e a descrição.
- **Bloqueio do "Inspecionar":** o site bloqueia o clique direito (menos nos campos de texto), o F12, os atalhos do DevTools (Ctrl+Shift+I/J/C, Ctrl+U e Cmd+Option+I/J/C/U no Mac) e o arrastar das fotos. Isso só **dificulta**: nenhum site consegue impedir de verdade que alguém veja o código. Para desligar, em `js/main.js` mude `bloquearInspecionar: true` para `false`.

## 13. Apontar `originalabc.com.br` para o GitHub Pages

> Hoje o domínio aponta para a hospedagem antiga (WordPress). Faça na ordem abaixo para o site não ficar fora do ar.

**Passo 0 — Anote o que existe hoje.** No Registro.br (ou no painel da hospedagem, ver passo 2), tire um print da zona DNS atual. Se a empresa usa **e-mail @originalabc.com.br**, os registros `MX` (e `TXT`/`SPF`) **não podem ser apagados**.

**Passo 1 — Verifique o domínio no GitHub (recomendado, evita que outra pessoa use o domínio).**
No GitHub: foto do perfil → **Settings → Pages → Add a domain** → digite `originalabc.com.br`. O GitHub mostra um registro `TXT` (nome parecido com `_github-pages-challenge-primol`). Crie esse `TXT` no DNS (passo 2) e volte para clicar em **Verify**.

**Passo 2 — Descubra onde o DNS é editado.** Em [registro.br](https://registro.br) → entre → clique no domínio → seção **DNS**:
- Se os servidores forem `a.auto.dns.br` / `b.auto.dns.br` (DNS do Registro.br): clique em **Configurar zona DNS / Editar zona** e edite lá.
- Se forem servidores de outra empresa (ex.: `ns1.hostinger...`, `dns1.locaweb...`): o DNS está na hospedagem antiga. Edite na **Zona DNS** do painel dela, **ou** troque para "Utilizar os servidores DNS do Registro.br" — nesse caso recrie lá todos os registros que existiam (principalmente os de e-mail).

**Passo 3 — Crie/edite os registros:**

| Tipo | Nome | Valor |
|---|---|---|
| A | *(vazio / @)* | `185.199.108.153` |
| A | *(vazio / @)* | `185.199.109.153` |
| A | *(vazio / @)* | `185.199.110.153` |
| A | *(vazio / @)* | `185.199.111.153` |
| CNAME | `www` | `primol.github.io` |
| AAAA *(opcional)* | *(vazio / @)* | `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` |

Apague os registros `A`/`AAAA`/`CNAME` **antigos** de `@` e de `www` que apontam para a hospedagem antiga. **Não mexa** em `MX` e nos `TXT` de e-mail.

**Passo 4 — Espere propagar** (de minutos até 24–48 h). Confira em [dnschecker.org](https://dnschecker.org) se `originalabc.com.br` já mostra os IPs `185.199.x.153`.

**Passo 5 — Ligue o domínio no repositório.** **Settings → Pages → Custom domain** → `originalabc.com.br` → **Save**. Espere aparecer "DNS check successful" e marque **Enforce HTTPS** (o certificado pode levar até algumas horas). O GitHub cria sozinho um arquivo `CNAME` no `main` — **não apague** esse arquivo.

**Passo 6 — Teste** `https://originalabc.com.br`, `https://www.originalabc.com.br` e um endereço antigo, como `https://originalabc.com.br/recuperacao-de-para-choque/` (deve abrir a página nova de Funilaria).

**Depois:** só cancele a hospedagem antiga quando o site novo estiver no ar **e** o e-mail (se houver) estiver garantido em outro lugar.

> Por que não fazer o passo 5 antes? Com o domínio ligado no GitHub e o DNS ainda apontando para a hospedagem antiga, o endereço `github.io` passa a redirecionar para o site **antigo** (foi o que aconteceu quando o `CNAME` foi criado e apagado). Por isso: DNS primeiro, domínio no GitHub depois.
